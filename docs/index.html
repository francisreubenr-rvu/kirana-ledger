The problem

India's neighbourhood shops run on trust and credit. The tools built for them assume the owner has a free hand and a free minute. They don't.

📒 Udhaar leaks

Credit lives in a paper khata or the owner's memory. Entries get missed in a rush, totals are added by hand, and asking a regular to pay up is awkward.

📦 Stock by eye

Reorders happen when a customer asks for something that has already run out.

📱 Apps need hands

Khata and POS apps want the owner to unlock a phone, find the customer and type an amount, mid-sale. That step is the one that gets skipped.

How it works

One button, one sentence, any of four languages, often mixed. The box writes only what a typed tool allows and reads back exactly what it wrote.

1

Hold and speak

The owner holds the button and talks naturally: “Lakshmi 300 kottru”, “Murugan ku 200 kadan”, “20 Maggi aaye”.

2

It understands

Sarvam Saaras v4 transcribes in codemix mode with the shop's own customer and product names as keyterms. Sarvam 105B turns the sentence into ledger tool calls, several per sentence if needed.

3

It writes and confirms

Tools update SQLite (money as integer paise). A fixed template in the owner's language is spoken back by Bulbul: “Lakshmi ಅವರಿಂದ 300 ರೂಪಾಯಿ ಬಂದಿದೆ. ಈಗ ಬಾಕಿ 900.”

4

Ask anything

“Suresh ka kitna baaki hai?” gets the balance read aloud, with no screen and no phone unlock.

5

Close the day

“Aaj ka hisaab” gives the day's sales, credit, collections and reorder list, plus a WhatsApp-ready summary.

6

Collect politely

One-tap WhatsApp reminders for every customer who owes, in Hindi, Kannada, Tamil or English. This is where a ledger turns into recovered cash.

Architecture

A small, domain-agnostic voice → tools loop. Every stage sits behind one interface and has an offline mock, so the counter never goes silent.

DeviceESP32-S3 + INMP441 mic records 16 kHz WAV while the button is held
→
STTSarvam Saaras v4, codemix, keyterms = known names
→
PlanSarvam 105B tool calls (any OpenAI-compatible LLM, or offline rules)
→
Act6 typed tools on SQLite: credit, payment, sale, stock, balance, summary
→
SpeakTemplate read-back via Bulbul v4, played on a MAX98357A amp
  owner speaks ─► ESP32-S3 ── HTTP POST /voice (WAV) ──►  FastAPI server (laptop or small VM)
                                                          1 STT     Saaras v4 (codemix + keyterms)
                                                          2 Plan    LLM tool calls ─┐  fallback: rule parser
                                                          3 Act     ledger tools ◄──┘  (SQLite, integer paise)
                                                          4 Confirm fixed hi / kn / ta / en template
  speaker  ◄── MAX98357A ◄──────────── reply WAV ◄─────── 5 TTS     Bulbul v4-flash, 16 kHz
                                                          /summary  WhatsApp day summary
                                                          /reminders wa.me links per debtor

Deterministic writes

The LLM only picks tools and arguments. It never writes free text into the books.

Graceful fallback

If the LLM times out or fails, a rule parser handles common phrasings for that utterance and the reply notes it.

Provider-swappable

STT, planner and TTS are each one small class. Point LLM_URL at any OpenAI-compatible endpoint.
